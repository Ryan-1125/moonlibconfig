# 维护与兼容政策

## 版本

使用语义化版本。0.x阶段，改变公开API或行为规则时提升minor；修复及文档改进提升patch。已发布版本不覆盖。新增或移除已知上游差异必须提供独立输入和双方结果，不能仅修改预期文件让测试通过。

## 回归门槛

提交保持格式、严格检查、三后端构建与测试通过。CI自动运行fuzz_wbtest中的固定种子语料：1000个字节突变输入及500个生成树。接受的输入必须通过独立校验且规范化往返保持值和类型。此为有界确定性模糊回归，不代替持续覆盖引导模糊测试。

新增发现应缩减成固定回归输入。保留原始种子、目标后端及工具链版本；不得吞掉非ConfigError异常。真实上游、ZIP消费和注册表消费分别保留证据。

## 性能基线

运行tools/Measure-Baseline.ps1，指定Target和Runs。脚本先预热，然后记录固定1000突变语料的端到端测试时间，结果存入.local/benchmarks。数字包含进程启动和测试框架开销，不作为解析器吞吐率或竞品性能声明。

仅在同机器、相同工具链、同一后端和相同样本数下比较。发现持续退化时先重复测量和定位，再决定是否阻止发布；不对共享CI机器设置未经校准的绝对时间阈值。
